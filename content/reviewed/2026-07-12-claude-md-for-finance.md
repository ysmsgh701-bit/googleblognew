# 비개발자 재무담당자의 CLAUDE.md 작성법 — AI에게 회계 규칙 가르치기

클로드 코드를 설치하고 며칠 써보면 누구나 같은 벽에 부딪힙니다. 시킬 때마다
똑같은 설명을 처음부터 다시 해야 한다는 것. "우리 회사 파이썬은 이 버전이고",
"이 계정들은 현금성자산으로 묶고", "숫자는 절대 임의로 만들지 말고"…
어제 분명히 말했던 규칙을 오늘 또 타이핑하고 있는 자신을 발견합니다.
이 문제를 해결하는 것이 바로 `CLAUDE.md`라는 문서이고, 이 글은 코드를
전혀 모르는 재무 실무자인 제가 이 문서를 실제로 어떻게 쓰고 있는지에 대한
기록입니다.

저는 지금 클로드 코드와 파이썬으로 해외법인(폴란드) 월마감·연결패키지
자동화를 진행하고 있습니다. 그 과정에서 코드는 한 줄도 직접 짜지 않았지만,
CLAUDE.md만큼은 제가 직접 씁니다. 왜 그런지부터 말씀드리겠습니다.

## CLAUDE.md가 뭐길래 — 매번 다시 설명하지 않는 방법

먼저 정보부터 정리하면, CLAUDE.md는 프로젝트 폴더에 만들어 두는 마크다운
문서입니다. 클로드 코드는 작업을 시작할 때마다 이 파일을 먼저 읽고, 거기
적힌 규칙을 따릅니다. 즉 대화가 새로 시작돼도 매번 유지되는 "상시 지시문"인
셈입니다. 특별한 문법도 없습니다. 그냥 한국어 문장으로 적으면 됩니다.

이 지점이 중요합니다. 문법이 없다는 것은, 프로그래머가 아니어도 쓸 수 있다는
뜻입니다. 설치 과정은 지난 글([클로드 코드 사용법 — 재무 실무자의 설치부터
첫 자동화까지](https://finance-ai-note.blogspot.com/2026/07/blog-post.html))에서
다뤘는데, 그때 제가 "진짜 넘어야 할 산은 설치가 아니라 내 업무 규칙을 문서로
명확하게 적는 것"이라고 썼습니다. 그 문서가 바로 이것입니다.

## 규칙 없이 시켰다가 겪은 일

제가 CLAUDE.md를 진지하게 쓰게 된 계기는 실패였습니다.
[월마감 자동화 첫 달 이야기](https://finance-ai-note.blogspot.com/2026/07/20-ai.html)에서도
고백했지만, 초기에 규칙을 촘촘하게 주지 않았더니 AI가 매핑이 애매한 계정을
"그럴듯하게" 추측해서 분류하려 했습니다. 코드 세계에서는 알아서 채워주는 게
친절일지 몰라도, 회계에서 추측은 재앙입니다. 틀린 분류가 연결패키지에
올라가면 그 숫자를 다시 파내는 데 몇 배의 시간이 듭니다.

그때 깨달았습니다. AI는 제 회사의 회계 규칙을 모릅니다. 제 컴퓨터 환경도
모릅니다. 제가 문서로 알려주지 않으면, AI는 일반론으로 움직입니다. 그리고
재무 업무에서 일반론은 곧 오류입니다.

## 재무 실무자의 CLAUDE.md 작성법 — 다섯 가지 항목

제 파일에 실제로 들어가 있는 내용을 항목별로 정리하면 이렇습니다.
거창한 것이 하나도 없다는 점에 주목해 주세요.

| 항목 | 무엇을 적나 | 제 파일의 실제 예시 |
|---|---|---|
| 실행 환경 | 내 컴퓨터의 특이사항 | "기본 python 말고 반드시 py -3.11 사용" |
| 금지 사항 | 절대 하면 안 되는 것 | "숫자는 절대 하드코딩하지 않는다" |
| 검증 규칙 | 산출물을 내도 되는 판정 기준 | "차변 합계 ≠ 대변 합계면 산출물을 만들지 않는다" |
| 애매할 때 규칙 | 판단을 유보하는 기준 | "매핑이 불분명한 계정은 추측하지 말고 목록에 남긴다" |
| 계정 매핑 | 우리 회사 계정 체계의 정의 | "이 계정 범위는 현금성자산이다" |

이 다섯 가지를 문장으로 옮기면 아래처럼 됩니다. 실제 제 프로젝트 규칙에서
가져온 예시입니다.

```markdown
# CLAUDE.md — 해외법인 월마감 자동화

## 실행 환경
- 이 컴퓨터의 기본 python은 다른 프로그램에 잡혀 있다.
  반드시 `py -3.11`을 사용한다.

## 절대 규칙 (위반하면 작업을 멈춘다)
1. 숫자를 절대 지어내지 않는다.
   모든 금액은 원본 데이터(원장)에서만 계산한다.
2. 차변 합계와 대변 합계가 다르면 산출물을 만들지 않는다.
   어디가 얼마나 틀렸는지만 보고하고 멈춘다.
3. 매핑이 불분명한 계정은 추측해서 분류하지 않는다.
   '미분류 목록'에 남긴다. 판단은 사람이 한다.

## 검증 규칙
- 원장 합계와 보고서 합계가 서로 일치하는지 매번 전 항목 확인한다.
- 매핑되지 않고 빠진 계정이 없는지 확인한다.
```

보시다시피 코드가 아니라 전부 한국어 문장입니다. 코드로 옮기는 일은 AI가
합니다. 저는 "무엇이 맞고 무엇이 틀렸는지"를 정의할 뿐입니다.

[이미지: 위 CLAUDE.md 예시가 프로젝트 폴더에 놓인 구조 다이어그램 (폴더 트리)]

## 제가 내린 결론: CLAUDE.md는 코드가 아니라 업무 인수인계서입니다

쓰다 보니 이 문서가 무엇을 닮았는지 알겠더군요. 신입 직원에게 주는
**업무 인수인계서**입니다. 우리 부서에서 20년 일한 사람이라면 "차대변이
안 맞으면 보고서를 올리면 안 된다"는 걸 몸으로 압니다. 하지만 신입에게는
문장으로 적어줘야 합니다. AI도 똑같습니다. 아주 똑똑하지만 우리 회사를
처음 보는 신입입니다.

그래서 저는 CLAUDE.md를 잘 쓰는 능력이 프롬프트 기술이 아니라 실무
경험이라고 생각합니다. "불분명한 계정은 추측하지 말고 남겨라" 같은 규칙은
검색해서 나오는 문장이 아닙니다. 새벽 결산에서 틀린 숫자를 파내 본 사람만
쓸 수 있는 문장입니다. 비개발자라서 불리한 게 아니라, 오히려 규칙을 정의할
도메인 지식이 있어서 유리한 지점이 여기입니다.

## 솔직한 한계도 적어둡니다

CLAUDE.md가 만능은 아닙니다. 제 경험상 두 가지는 미리 아셔야 합니다.

첫째, 처음부터 완성된 문서를 쓸 수 없습니다. 제 파일의 규칙들은 전부
사고가 난 뒤에 한 줄씩 추가된 것입니다. 파이썬 버전이 꼬여서 한 줄,
AI가 추측 분류를 해서 한 줄. 처음부터 완벽하게 쓰려고 하면 시작을 못 합니다.
빈 파일로 시작해서, 같은 설명을 두 번 하게 되는 순간마다 한 줄씩 옮겨
적는 방식을 권합니다.

둘째, 문서가 있어도 AI는 가끔 시키지 않은 것까지 알아서 하려는 성격이
있습니다. 그래서 저는 "하지 마라"뿐 아니라 "위반하면 멈추고 보고만 해라"까지
적습니다. 금지만 하면 우회하고, 멈추라고 해야 멈춥니다. 그리고 멈춘 뒤의
판단은 여전히, 앞으로도, 사람의 몫입니다.

## 정리하면

- CLAUDE.md는 클로드 코드에게 매번 다시 설명하지 않기 위한 상시 규칙 문서입니다.
- 문법이 아니라 한국어 문장으로 씁니다. 그래서 비개발자도 쓸 수 있습니다.
- 들어갈 내용은 실행 환경, 금지 사항, 검증 규칙, 애매할 때 규칙, 계정 매핑 —
  즉 신입에게 줄 인수인계서와 같습니다.
- 완성본을 목표로 하지 말고, 사고 날 때마다 한 줄씩 키우세요.

다음에는 이 규칙 문서 위에서 실제로 돌아가는 작업, PDF 청구서를 엑셀로
옮기는 자동화를 다뤄볼 예정입니다.
